# إعداد وإكمال المشروع على جهاز جديد

دليل كامل بالأوامر لتجهيز مشروع **تحكّم** على جهاز ثانٍ (Windows) ومتابعة النشر. نفّذ الخطوات بالترتيب.

> تنبيهات عامة لهذا الجهاز:
> - تشغيل سكربتات PowerShell معطّل، لذلك تُشغَّل بـ `powershell -ExecutionPolicy Bypass -File ...`.
> - استخدم `npx.cmd` (وليس `npx`).
> - مجلد `supabase-backend/secrets/` ومفاتيحه **لا تُرفع إلى Git أبداً** (متجاهلة). الموجود في المستودع هو `secrets.enc` المشفّر فقط.
> - ارفع إلى GitHub فقط عند الحاجة، وبعد فحص عدم وجود أسرار.

---

## 0) المتطلّبات (مرة واحدة لكل جهاز)

- **Git** — لاستنساخ المستودع والرفع.
- **Node.js** (يأتي معه `npx`) — لتشغيل Supabase CLI واختبارات الخادم.
- **Windows** — فيه مصرّف C# المدمج (`csc.exe` في `C:\Windows\Microsoft.NET\Framework64\v4.0.30319`). المصرّف **C# 5**: بلا `?.` ولا `$""` ولا `nameof` ولا tuples.
- وصول إلى مستودع GitHub الخاص `slmiksa/tahakkum`.
- للنشر على الخادم: أداة `scp`/`ssh` (موجودة في Windows حديثاً).

---

## 1) اسحب المشروع

أول مرة (استنساخ في مجلد فارغ — لا تستنسخ المستودع داخل نفسه):

```bash
git clone https://github.com/slmiksa/tahakkum.git
```

إن كان موجوداً مسبقاً، حدّثه فقط:

```bash
git pull
```

ثم ادخل مجلد المشروع في طرفيّتك قبل بقية الأوامر.

---

## 2) استرجع الأسرار (مفاتيح Supabase)

المفاتيح (`functions.env` = `LICENSE_SIGNING_KEY` و`CODES_KEY`، و`license-signing-key.json`) ليست في Git. استرجعها من `secrets.enc` المشفّر:

```bash
powershell -ExecutionPolicy Bypass -File supabase-backend\tools\secrets-unlock.ps1
```

يطلب **"Password for the secrets file"** = كلمة سر الأسرار التي تعرفها أنت فقط. تُكتب في الطرفية ولا تُشارك في أي مكان آخر.

> هذه الكلمة تخصّ **صندوق الأسرار فقط**، وتختلف عن كلمة سر قاعدة بيانات Supabase ودخول حساب Supabase.
>
> لتغيير كلمة سر الأسرار لاحقاً، راجع القسم (7).

---

## 3) سجّل الدخول واربط Supabase

مرة واحدة لكل جهاز (يلزم قبل النشر):

```bash
supabase-backend\tools\login.cmd
```

- **`supabase login`** → يفتح **المتصفح** لتسجيل الدخول بحساب Supabase (يأخذ التوكن تلقائياً — ليس كلمة في الطرفية).
- **`supabase link`** → يربط المشروع `hosmafqkcmcmdpwhzodu`، وقد يطلب **كلمة سر قاعدة البيانات** (تُكتب في الطرفية ولا تظهر أثناء الكتابة).

## 4) ابنِ واختبر (للتحقق — اختياري)

**بناء برنامج العميل** (يفشل لو كان `Tahakkum.exe` قيد التشغيل من مجلد dist):

```bash
powershell -ExecutionPolicy Bypass -File client-program\build.ps1
```

**اختبارات الخادم** (هجرات حقيقية على PGlite):

```bash
cd supabase-backend
npm install
node --test tests/licensing.test.ts
```

**معاينة اللوحة ببيانات وهمية** ثم افتح `http://127.0.0.1:47890` (المستخدم `salem`، كلمة `demo`، الرمز `123456` — وهمي للمعاينة فقط):

```bash
node supabase-backend/tests/dashboard-preview.ts
```

## 5) النشر

### أ) Supabase (قاعدة البيانات + الدوال)

```bash
supabase-backend\tools\deploy.cmd
```

يُنفّذ: `db push --remote` + ضبط المفاتيح من `secrets/functions.env` + نشر الدوال الخمس (activate, refresh, issue-batch, export-batch, admin-users).

> إن احتجت إرسال جسم JSON لدالة يدوياً على Windows، أرسله **من ملف** (`curl.exe ... --data "@body.json"`) وليس مضمّناً، لأن PowerShell يفسد علامات الاقتباس.

**تحقّق بعد النشر** (من خارج النظام):
- كود خاطئ لـ `activate` يرجع `invalid_code`.
- `admin-users` بلا مصادقة يرجع `403 not_admin`.
- الجداول غير مقروءة بالمفتاح العام (`401 permission denied`).

### ب) لوحة الخادم (Linux)

انسخ المثبّت من Windows، ثم شغّله على الخادم بمساره الكامل (تفادياً لتشغيل نسخة قديمة بالخطأ):

```bash
scp release\tahakkum-dashboard-install.sh USER@82.47.165.29:/tmp/tahakkum-new.sh
```

ثم على الخادم عبر SSH:

```bash
bash /tmp/tahakkum-new.sh
```

المثبّت مكتفٍ ذاتياً وآمن لإعادة التشغيل، ويطبع `DASHBOARD IS RUNNING` عند النجاح. بعدها حدّث المتصفح بتجاهل الكاش (`Ctrl + Shift + R`). مثبّت الريلاي على نفس النمط: `release\tahakkum-relay-install.sh`.

### ج) برنامج العميل

أعد توليد الحزم بعد أي تغيير في `client-program` أو `dashboard` أو `relay-server`:

```bash
powershell -ExecutionPolicy Bypass -File package-release.ps1
```

ثم وزّع `release\tahakkum-client.zip` على أجهزة العملاء. التفعيل الصامت للنشر الجماعي:

```bash
Tahakkum.exe /activate <الكود>
```

(exit code 0 = نجح التفعيل، 1 = فشل.)

## 7) تغيير كلمة سر صندوق الأسرار

على جهاز **يحوي مجلد `secrets/` مفكوكاً** (مثل جهازك الأساسي): يعيد التشفير بنفس المفاتيح وكلمة سر جديدة — لا يمسّ مفتاح التوقيع، فلا يتعطّل أي ترخيص.

```bash
powershell -ExecutionPolicy Bypass -File supabase-backend\tools\secrets-lock.ps1
```

ثم ارفع `secrets.enc` الجديد:

```bash
git add supabase-backend/secrets.enc
```

```bash
git commit -m "Re-encrypt secrets.enc with a new archive password"
```

```bash
git push origin main
```

> ⚠️ لو فقدت ملفات `secrets/` **و** نسيت كلمة السر معاً، يضيع مفتاح التوقيع نهائياً ولا يمكن إعادة نشر الدوال بنفس المفتاح. احفظ الكلمة في مدير كلمات سر، واحتفظ بنسخة احتياطية آمنة من `secrets/` (غير مشفّرة أبداً في Git).
