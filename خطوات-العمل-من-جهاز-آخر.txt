مشروع تحكّم: خطوات إكمال العمل من جهاز آخر
==========================================

المشروع محفوظ في GitHub (خاص): slmiksa/tahakkum
كل الكود والملاحظات هناك. المفاتيح السرية محفوظة فيه مشفّرة بكلمة سرك فقط.


قبل أن تترك الجهاز الحالي
-------------------------
قل لـ Claude: "ارفع التحديثات"
حتى يصل آخر عمل إلى GitHub. ما لم يُرفع يبقى على الجهاز القديم فقط.


على الجهاز الجديد (مرة واحدة فقط)
---------------------------------
1) ثبّت الأدوات. افتح PowerShell واكتب كل سطر وحده:

   winget install --id Git.Git -e
   winget install --id GitHub.cli -e
   winget install --id OpenJS.NodeJS.LTS -e

   ثم أغلق PowerShell وافتحه من جديد.

2) سجّل الدخول إلى GitHub:

   gh auth login

   اختر: GitHub.com ثم HTTPS ثم Login with a web browser.
   انسخ الرمز الذي يظهر، وأدخله في الصفحة التي تفتح.
   (اجعل لوحة المفاتيح إنجليزية قبل الكتابة.)

3) انسخ المشروع إلى سطح المكتب:

   cd $env:USERPROFILE\Desktop
   gh repo clone slmiksa/tahakkum control

   مهم: نفّذه مرة واحدة فقط، ومن سطح المكتب، وليس من داخل مجلد control.

4) استرجع المفاتيح السرية:

   cd $env:USERPROFILE\Desktop\control
   powershell -ExecutionPolicy Bypass -File .\supabase-backend\tools\secrets-unlock.ps1

   اكتب كلمة سر الملف المشفّر عندما يطلبها.
   إذا نجح يظهر: Restored 2 files

5) افتح Claude Code على مجلد control وقل له:
   "غيّرت الجهاز، اسحب آخر التحديثات"


كل مرة تبدأ العمل
-----------------
- إذا كنت تتنقل بين الأجهزة، ابدأ بقول: "اسحب آخر التحديثات"
- وعند الانتهاء: "ارفع التحديثات"
- هكذا يبقى المشروع نسخة واحدة صحيحة في كل الأجهزة.


تنبيهات مهمة
------------
- لا تكتب كلمة سر الملف المشفّر في المحادثة أبداً، ولا في أي ملف.
  احفظها في مكان آمن خارج الجهاز. بدونها لا يمكن فتح المفاتيح.
- لا ترسل مجلد supabase-backend\secrets لأحد، ولا ترفعه بنفسك.
- إذا ضاع مفتاح توقيع الرخص، تتوقف كل الرخص الصادرة.
- النشر على Supabase تشغّله أنت بنفسك:
  supabase-backend\tools\deploy.cmd
- إذا تغيّرت المفاتيح يوماً، شغّل بنفسك:
  powershell -ExecutionPolicy Bypass -File .\supabase-backend\tools\secrets-lock.ps1
  ثم قل لـ Claude: "ارفع التحديثات"
